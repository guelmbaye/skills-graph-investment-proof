# Skills Graph — Skills Investment Proof

> **See which training investments are feasible—and which skills pathways they affect.**
>
> Relate by Neo4j Hackathon 2026 | Independent new project started in the contest period | **Synthetic data only**.

## Use case

A regional training planner announces 180 seats across three programs. Two programs require the same cybersecurity lab, so a capacity disruption can affect training feasibility. A simple count of graph links may wrongly label a related occupation as negatively affected even when its limiting skill remains unchanged.

**Skills Investment Proof** uses the actual graph to connect:

`Resource ← USES_RESOURCE — Program — DEVELOPS → Skill ← REQUIRES — Occupation`

It answers two separate questions:

1. Which training programs have fewer **plan-feasible** seats after a capacity change?
2. Which occupation **bottleneck proxies** change, after considering other programs that cover the required skills?

The second result is NOT a forecast of employment or certified skill acquisition.

## What is demonstrated

Synthetic scenario, shared `LAB-SOC` capacity **140 → 100 → 140**:

| Indicator | A | B | Restored A |
|---|---:|---:|---:|
| Total feasible training seats | 180 | 140 | 180 |
| Cloud Security program | 60 | 20 | 60 |
| SOC Operations program | 80 | 80 | 80 |
| Data Analysis program | 40 | 40 | 40 |
| Cloud Security Engineer bottleneck proxy | 60 | 20 | 60 |
| SOC Analyst bottleneck proxy | 80 | 80 | 80 |

`SOC-ANALYST` is structurally connected to the changed program via `SIEM` but **does not lose bottleneck-proxy capacity** because `INCIDENT` is still the limiting skill. This is the central demonstration: *connected ≠ affected*.

## How it uses Relate—and why

**Mode: Single file**, embedded Relate Python package `relate-db==1.0.1` with persistent `.rl` graph.

- `skills_graph/relate_backend.py` creates `Resource`, `Program`, `Skill` and `Occupation` nodes, with typed relationships and Cypher traversals.
- `skills_graph/webapp.py` reads actual graph data through Cypher on each evaluation, alters lab capacity for B and restores state A, and refuses a result that differs from the JSON/Python baseline.
- `skills_graph/experience.py` separates structural paths from observed program changes and occupation bottleneck proxies.
- `web/` provides a no-build frontend with graph visualization and visible error states.

Why single file? The competition demo runs on one local developer machine, so a portable, inspectable `.rl` store avoids server infrastructure. The file `data/demo.rl` is a **synthetic example** committed for judges; the app creates a fresh working copy in `build/` at launch.

Relate is the **source of graph relationships** for the interactive demo. Arithmetic scheduling follows a deterministic fixed-priority method; we **do not** claim the graph optimizes allocations better than OR-Tools, relational joins or a spreadsheet.

## Setup and run (Windows / PowerShell)

Requirements: Python 3, Windows PowerShell, and internet access for first-time installation. From repo root:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m skills_graph.webapp --store build/judge-run-1.rl --port 8765
```

Open http://127.0.0.1:8765/ and use the slider. The browser should display `Relate 1.0.1 · connected` and the dependency graph. Try 100, then restore 140. Stop the server with Ctrl+C.

**Important:** the backend **refuses to overwrite an existing `.rl` file**. For another run, use a fresh filename such as `build/judge-run-2.rl`. The server only binds to localhost.

Console-only alternative, using a fresh file:

```powershell
python -m skills_graph.demo --backend both --store build/judge-cli-1.rl --report build/judge-report.json
```

## Persistent graph location

**Committed sample:** `data/demo.rl` (must be generated on a Relate-enabled host and added before publication).

**Runtime store:** `build/judge-run-1.rl` (generated by the app, deliberately gitignored).

To generate the sample from the working UI Fix package, stop the local server and copy its **synthetic** `build/skills_graph-t3-uifix-run1.rl` file to `data/demo.rl`. Verify that the committed file can be opened. Do not put personal or production data in the repository.

## Reproducibility and boundaries

- User-provided Windows screenshots on 14 November 2026 confirm a functioning local T3 UI Fix demo at lab capacity 100, including visible graph, Relate connected status and A/B/A parity indicators. The screenshots are not a broad independent performance benchmark.
- Pure Python baseline and Relate run on the same synthetic fixture. Equality of outcomes is **by design**.
- No live training institution, real learner record, job posting dataset or employment data is included.
- Seat-opportunity totals and minimum-skill proxies are **not counts of graduates, qualified individuals, employment outcomes, or policy benefits**.
- Program scheduling uses fixed-priority greedy allocation, **not** globally optimal scheduling.
- The app is local-only and should not be exposed publicly without a separate security review.
